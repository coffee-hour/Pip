### DOC: sovereign-philosophy
A sovereign tool is one you control. It runs on hardware you own, keeps your data on your disk, and works when the network is down. You can read its source, change it, and turn it off. Sovereignty does not mean isolation. It means that the choice to connect is yours, made case by case, and that no outside party can quietly change the terms under you.
Three practical tests help. First, can it run offline? Second, can you export your data in an open format? Third, can you inspect what it sends over the network? A tool that fails any of these depends on someone else's goodwill.

### DOC: sovereign-philosophy-2
A companion that serves you should be honest about what it is. It should say when it does not know, say when a claim needs checking, and never pretend to remember or feel things it cannot. Loyalty means telling you the truth you need, even when it is inconvenient, and then respecting your decision.

### DOC: hardware-diagnostics-power
A machine that will not power on: first check the power source. Confirm the outlet works, the cable is seated, and the power brick LED is lit. On a laptop, remove the battery if it is removable, hold the power button for 15 seconds, reconnect power, and try again. Listen for fans or a beep. No sound and no light usually points to the power supply, the motherboard power circuit, or a dead battery. A machine that powers on but shows no display: check the cable to the monitor, try a second display, and listen for beep codes. Beep codes differ by manufacturer, so look up the code in the motherboard or laptop manual.

### DOC: hardware-diagnostics-thermal
Overheating shows up as throttling, sudden shutdowns under load, loud fans, or hot exhaust. Check fan operation first. Then check whether the intake and exhaust vents are blocked by dust or by the surface the device sits on. Use a monitoring tool to read temperatures under load. On Linux, the sensors command from lm-sensors reads them. On Windows and macOS, use the vendor utility or a third-party monitor. Sustained temperatures near the rated maximum mean cleaning, re-seating the heatsink, or replacing old thermal paste is worth doing. Do not run a machine that shuts down from heat on a soft bed or carpet.

### DOC: hardware-diagnostics-storage
A failing drive often shows slow reads, repeated file errors, clicking, or disappearing volumes. Back up first, before any repair attempt. On Linux, run smartctl -a /dev/sdX from smartmontools to read the SMART health data. Watch reallocated sector count, pending sectors, and uncorrectable errors. Any rising count on a spinning disk is a warning. A drive that clicks repeatedly should be powered down and sent for professional data recovery rather than tested again and again. Running fsck or chkdsk on a failing disk can make things worse.

### DOC: hardware-diagnostics-memory
Random crashes, blue screens, and corrupted files can come from bad RAM. Run a memory test. On most systems, memtest86 or memtest86+ from a bootable USB stick works well. Test one memory module at a time if the machine has more than one, so you can identify the bad stick. Errors found by the test are a clear sign to replace that module.

### DOC: repair-procedure-general
A safe repair follows a fixed order. One, record the symptom exactly, including any error text. Two, remove power, unplug the charger, and for laptops disconnect the battery if it can be removed. Three, back up any data you can reach. Four, change one thing at a time and note what changed. Five, test after each change. Six, if you open the device, photograph each step and keep the screws sorted in a labeled tray. Stop and ask for help when you do not know what a part does.

### DOC: repair-procedure-static
Static discharge can kill components without any visible sign. Work on an anti-static mat if you have one, or touch an unpainted metal part of the chassis before handling boards. Hold cards by their edges. Do not touch the gold connector pins. Keep the device unplugged while you work inside it.

### DOC: repair-procedure-laptop-battery
A laptop battery that drains fast or will not charge may be worn. Check the battery health report. On Windows, run powercfg /batteryreport in an elevated terminal and open the HTML file it writes. On macOS, check System Information or the battery menu for the service status. On Linux, check the battery capacity files under /sys/class/power_supply. A battery that is swollen must be stopped from use immediately and taken to a recycler that accepts lithium batteries. Do not puncture or charge a swollen battery.

### DOC: repair-procedure-screen
A cracked or flickering laptop screen: first check the external output. If the external monitor works, the problem is likely the panel or its ribbon cable. Flicker that changes when you flex the lid often points to the display cable. Reseat the cable with power off. Test with a known good panel if one is available. Panel replacement is a precise job, so match the exact model number on the back of the old panel.

### DOC: bash-basics-navigation
Useful shell commands for getting oriented: pwd prints the current directory. ls -la lists files with hidden files and permissions. cd moves you. cd - returns to the previous directory. find . -name "*.log" finds files by name. du -sh * shows the size of each item in the current directory. df -h shows free space on mounted filesystems.

### DOC: bash-basics-files
To read a file, use cat for short files, less for long ones, and head or tail -n 50 for the start or end. tail -f follows a log as it grows. To search inside files, use grep -rn "pattern" . which searches recursively and prints line numbers. Use cp -r to copy directories and mv to move or rename. Use rm -i when you want a confirmation prompt before deleting.

### DOC: bash-basics-permissions
File permissions show as rwxr-xr-x. The three groups are owner, group, and others. chmod +x script.sh makes a script executable. chmod 600 secret.txt restricts a file to its owner. chown changes ownership and usually needs sudo. Never run chmod -R 777 as a fix. It opens files to everyone and hides the real problem.

### DOC: bash-pipes-and-redirection
A pipe sends one command's output into another: ps aux | grep python. Redirect output to a file with > to overwrite or >> to append. Redirect errors with 2>. Combine with 2>&1 to send both to the same place. For a quick check, command | head works. Use set -euo pipefail at the top of a bash script so it stops at the first error instead of carrying on with bad data.

### DOC: bash-safety
Before running a destructive command, read it twice. rm -rf with an empty or wrong variable can delete far more than intended. Quote variables: rm -rf "$DIR/" is safer than rm -rf $DIR/. Test with echo first. Keep backups before bulk changes. Use dry-run flags when a tool has them, such as rsync -n.

### DOC: bash-process-management
To see what is running, use ps aux or top. htop is friendlier if installed. To stop a process politely, use kill PID. Use kill -9 PID only when a process ignores the normal signal. To find which process holds a port, use ss -ltnp or lsof -i :8000. Run a command in the background with nohup command & and check it later with jobs or ps.

### DOC: bash-network-basics
To check connectivity, ping -c 4 host sends four packets. To see listening ports, use ss -tuln. To test a web server, use curl -I https://example.com to see headers only. To check DNS, use dig example.com or nslookup. A local-only server on 127.0.0.1 is reachable only from that machine. Binding to 0.0.0.0 makes it reachable from the network, so do that only on purpose.

### DOC: bash-git-basics
git status shows what changed. git diff shows the exact edits. git add file stages it and git commit -m "message" records it. git log --oneline shows the history. Check git status before a commit to be sure you are committing only what you meant to. Never commit secrets, tokens, or checkpoints. Put them in .gitignore.

### DOC: python-venv
To keep packages isolated, create a virtual environment: python3 -m venv .venv, then source .venv/bin/activate on Linux or macOS. Install with pip install -r requirements.txt. Confirm the right interpreter with which python. Deactivate with deactivate.

### DOC: ml-checkpoints-and-tokens
A checkpoint is a saved set of model weights, often with optimizer state. Keep checkpoints out of git because they are large. A tokenizer turns text into integer ids. A byte-level tokenizer starts from the 256 byte values and adds merges, so any text can be encoded. A plain text corpus for training should be UTF-8, with clear section boundaries so the model learns the shape of each example.

### DOC: ml-data-hygiene
Good training data is accurate, consistent in format, free of secrets and personal details, and matched to the job the model will do. Remove duplicates. Check that every example is complete. Do not include private identifiers, passwords, or another person's private data unless the owner has agreed to it and it is needed for the task.
